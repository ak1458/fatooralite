# FINDINGS REGISTER — FatooraLite Pro production audit

Evidence standard: every entry below was reproduced against a running build
(`next start`, NODE_ENV=production, AUTH_ENFORCE=true) backed by an isolated
`fatoora_audit` database seeded with two independent tenants.

---

## F-01 — Logout did not revoke the session server-side
- **Ledger:** M-007, M-008, A-087, A-276, A-277
- **Status:** FAILED → FIXED → RETESTED → GREEN
- **Severity:** High
- **Component:** `app/api/auth/logout/route.ts`, `app/api/auth/me/route.ts`
- **Evidence (before):** `logout=200 reuse-of-old-cookie=200` — after POST /api/auth/logout the same cookie still authenticated. Session is a stateless 7-day HS256 JWT; nothing invalidated it.
- **Impact:** "Sign out" gave no protection to anyone whose cookie had been captured (shared machine, copied cookie jar, proxy/backup capture). Token remained valid up to 7 days.
- **Fix:** Logout now increments `User.sessionVersion` — the revocation mechanism the schema already had for password resets — and `/api/auth/me` performs the same version check `requirePermission` does.
- **Retest:** `before=200 logout=200 me.user=null protected-after=401`; tenant B unaffected (`status=200`). Regression tests in `app/api/auth/logout/route.test.ts` (2 passing).
- **Trade-off recorded:** the JWT has no per-session id, so this signs the user out on every device.

## F-02 — Rate limiter defeated by rotating X-Forwarded-For
- **Ledger:** A-148, M-034, A-282
- **Status:** FAILED → FIXED → RETESTED → GREEN
- **Severity:** Medium (High for self-hosting)
- **Component:** `proxy.ts`, new `lib/ratelimit/client-ip.ts`
- **Evidence (before):** the entire raw header was the bucket key, so a new value per request minted a new bucket. 0/14 credential requests blocked while rotating the header.
- **Fix:** read the address from the **right** of the forwarded chain (`TRUSTED_PROXY_HOPS`, default 1) so caller-prepended entries are ignored.
- **Retest:** 130 requests with a rotating spoofed prefix behind a fixed real client → **30/130 blocked, 100 allowed** — identical to the honest single-client control. 7 unit tests in `lib/ratelimit/client-ip.test.ts`.
- **Residual (documented, not fixable in app code):** deploying with no reverse proxy leaves the header fully caller-controlled.

## F-03 — Email case mismatch caused permanent password-reset lockout
- **Ledger:** M-001, M-002, M-004, A-281
- **Status:** FAILED → FIXED → RETESTED → GREEN
- **Severity:** Medium-High
- **Component:** `lib/validation/schemas.ts`, `app/api/auth/login/route.ts`
- **Evidence (before):** registration and login compared the raw string; `/api/auth/forgot` looked up `email.toLowerCase()`. Live: login as `OWNER-A@AUDIT.EXAMPLE` → **401**. A user who signed up with any capital letter could sign in but could never reset their password — and that endpoint returns a generic success by design, so the failure was silent. The same gap let `a@x.com` and `A@x.com` register as two accounts (`User.email` unique is case-sensitive).
- **Fix:** shared `emailField` normalises (trim + lower-case) before validation, used by register, login and invite.
- **Retest:** login with upper-case → **200**; duplicate registration with different case → **409**. 5 tests added.
- **Data check:** 0 of 3 existing users had a non-lower-case address, so no backfill was required.

## F-04 — Unvalidated login body produced attacker-triggerable 500s
- **Ledger:** A-139, A-146, A-147, M-035
- **Status:** FAILED → FIXED → RETESTED → GREEN
- **Severity:** Medium
- **Component:** `app/api/auth/login/route.ts`
- **Evidence (before):** `{"email":{"contains":"@"}}` reached Prisma as a where clause → 500. Nothing was bypassed (Prisma rejects the shape) but the endpoint could be made to error on demand.
- **Fix:** `loginSchema` validates before any DB access; password checked for presence only, so the endpoint does not disclose the password policy.

## F-05 — NUL byte in any path/query segment produced an unhandled 500
- **Ledger:** A-147, A-145, M-035, M-439
- **Status:** FAILED → FIXED → RETESTED → GREEN
- **Severity:** Low-Medium
- **Component:** `proxy.ts`
- **Evidence (before):** fuzzing 10 routes × 12 payloads produced 13 5xx responses — `?status=%00`, `/api/audit/%00`, `/api/invoices/%00/pdf`, `/api/companies/%00`. PostgreSQL rejects NUL inside a text value.
- **Fix:** rejected centrally with 400 in the proxy, covering every current and future route rather than patching each one.
- **Retest:** `?status=%00` → **400**.
- **Residual:** invalid UTF-8 sequences (`%ff%fe`, `%e0%80%af`) still yield a framework-level 500 from Next.js's own URL decoding, before application code runs. Body is a generic "Internal Server Error" with no internals disclosed. Recorded as RISK, not fixed.

## F-06 — ZATCA CSID secret stored in clear text
- **Ledger:** M-030, M-193, A-081, A-086
- **Status:** RISK → FIXED → RETESTED → GREEN
- **Severity:** High
- **Component:** `lib/services/onboarding-service.ts`, `lib/crypto/encrypt.ts`, `lib/db/repo.ts`
- **Evidence:** `Certificate.privateKey` was wrapped with AES-256-GCM, but `Certificate.secret` — the other half of the HTTP Basic credential presented to the Fatoora gateway (`lib/zatca/client.ts:100`) — was written as clear text at three sites.
- **Impact:** anyone with database read access (a backup, the Neon console, a leaked `DATABASE_URL`) could authenticate to ZATCA as that taxpayer.
- **Fix:** `encryptSecret`/`decryptSecret` added; all three write sites wrap, all read sites unwrap. Legacy clear-text rows are detected by shape and returned unchanged, so no migration is required and nothing breaks.
- **Retest:** 6 tests in `lib/crypto/encrypt.test.ts`, including GCM tamper rejection. Full suite green.
- **Note:** the only existing certificate row holds the public constant `LOCAL-DEV-SECRET`, so no real credential was exposed in the current database.

## F-07 — Working tenants were told they had no certificate
- **Ledger:** M-063, M-220, M-221, M-064, A-227
- **Status:** FAILED → FIXED → RETESTED → GREEN
- **Severity:** Medium
- **Component:** `app/api/integration/route.ts`, `app/api/clearance/route.ts`
- **Evidence (before):** both filtered `kind: "production"`. Since the relabel migration, locally-provisioned certificates carry `kind: "local"`, so the query matched nothing. Live: tenant A held an active certificate and had signed `INV-2026-00001`, yet `/api/integration` returned `{"certificate":null,"canIssue":false,"canClear":false}`.
- **Fix:** match on `status: "active"` (what actually governs signing, as `getActiveCertificate` does) and derive `isLocal` from `kind`.
- **Retest:** `{"certificate":{"serial":"LOCAL-DEV","isLocal":true,"daysLeft":364},"canIssue":true,"canClear":false}` — correct and honest.
- **Checked and deliberately left alone:** `lib/db/queries.ts:17,180` and `app/api/companies/[id]/route.ts:75` also query `kind:"production"`, but correctly — they distinguish a real production CSID from a local certificate on purpose.

## F-08 — 18 licensing tests had never executed
- **Ledger:** M-476..M-478, M-495, A-013
- **Status:** FAILED → FIXED → RETESTED → GREEN
- **Severity:** Medium (test integrity)
- **Component:** `lib/billing/plan.test.ts:37`
- **Evidence:** `makeCompany()` incremented `seq` for the company name but hard-coded `vatNumber: "300000000000003"` on a `@unique` column, so every company after the first failed. CI skips the suite (no `TEST_DATABASE_URL`), so all 18 assertions had never run.
- **Fix:** VAT number now varies with `seq`, keeping the 15-digit ZATCA shape.

## F-09 — Stale expectation in the repository test

- **Severity:** Low
- **Component:** `lib/db/repo.test.ts:47`

## OPEN — recorded, not fixed

## F-10 — `confirmedAction` in the AI agent is a client-trusted flag
- **Ledger:** M-365, M-361, A-302
- **Status:** RISK (open)
- **Component:** `app/api/ai/agent/route.ts:58-69`
- **Detail:** the client resends `{name, arguments}` and the server executes it. Nothing binds that payload to what the model proposed and a human approved, so the confirmation step is a UX affordance, not a security boundary. RBAC and zod validation are still enforced underneath, so a caller can only invoke tools they are already entitled to — this is defence-in-depth, not a privilege escalation.
- **Recommended:** mint a short-lived single-use token keyed to `{userId, companyId, tool, argsHash}` (already on the project's own backlog).

## F-11 — Any tenant owner can force a global RAG re-index
- **Ledger:** M-331, M-347, A-220, A-131
- **Status:** RISK (open)
- **Component:** `app/api/ai/ingest/route.ts:42-46`
- **Detail:** `POST {scope:"global"}` requires only `settings:manage` — held by every tenant owner — and clears and re-embeds the shared ZATCA corpus for *all* tenants. The corpus is a code constant, so no cross-tenant data injection is possible, but the blast radius of a per-tenant permission is global and each call spends embedding budget. There are no per-customer AI usage limits anywhere.
- **Recommended:** restrict global scope to an operator credential; add per-tenant AI quotas.

## F-12 — CSRF check is skipped when Origin and Referer are both absent
- **Ledger:** A-141, M-033
- **Status:** RISK (accepted, documented)
- **Component:** `proxy.ts:104-117`
- **Detail:** verified live — a POST with neither header succeeds (201). Modern browsers always send `Origin` on non-GET, so this is not browser-reachable; it only affects non-browser clients, which are not the CSRF threat model. Cookie is `SameSite=Lax`, which independently blocks the cross-site case.

## F-13 — Password-reset email delivery is unconfigured by default
- **Ledger:** M-004, M-449
- **Status:** PARTIAL
- **Component:** `lib/email/send.ts`, `app/api/auth/forgot/route.ts`
- **Detail:** `RESEND_API_KEY` is optional and commented out in `.env.example`; without it the reset link is only `console.log`ged. The token itself is not written to the log (the 200-char preview truncates before the URL), but a customer who forgets their password has no self-service recovery path in a default deployment.

## F-14 — Reset URL is built from a request header, not the canonical app URL
- **Ledger:** M-004, M-459
- **Status:** RISK (open)
- **Component:** `app/api/auth/forgot/route.ts:64`
- **Detail:** `req.headers.get("origin") ?? "http://localhost:3000"`. A canonical `appUrl()` helper exists in `lib/appUrl.ts` and is used by robots/sitemap/OpenGraph, but not here. Token exfiltration via a forged Origin is **blocked** by the proxy's CSRF check (verified: 403), so this is a correctness/fragility issue rather than an exploitable one — a caller that sends no Origin gets a `localhost:3000` reset link.
- **Recommended:** use `appUrl()`.

## F-15 — `APP_URL` is required but undocumented
- **Ledger:** M-459, M-463
- **Status:** RISK (open)
- **Component:** `app/api/billing/checkout/route.ts:31-33`, `.env.example`
